# brownbot

A personal AI assistant that runs on **your own Mac**, talks to you over **iMessage**, and works as a second brain: executive assistant, household coordinator, and a knowledge layer that actually remembers.

You message it (with a trigger word in group chats, or directly in a DM); it routes to the right context, runs a Claude tool-use loop with a scoped set of tools, and replies in the same thread. It also works proactively — a morning brief, calendar prep, a nightly reflection that connects the dots across your week, and organic reminders that escalate, then go quiet on their own instead of nagging.

Everything stays local. The whole brain is a single SQLite file on your machine. The dashboard is loopback-only. Nothing about you is in this repo — your assistant's identity, voice, and knowledge are generated on your machine by onboarding and never committed.

> **Built it for myself, opened it up.** This is a real working system someone runs every day, generalized so you can run your own. The architecture lives in [`CLAUDE.md`](./CLAUDE.md); a condensed tour is in [`docs/ARCHITECTURE.md`](./docs/ARCHITECTURE.md).

## Quickstart

```bash
git clone https://github.com/manavpthaker/brownbot
cd brownbot
npm install
npm run onboard
```

`npm run onboard` is **the Mirror** — a short conversation that interviews you (who you are, who's in your circle, how you want it to talk to you, which areas to turn on) and then generates everything: your assistant's identity and voice, an always-on profile, seed facts, per-group context, and your `.env`. Want to see what it produces without touching anything? `npm run onboard:dry` writes to a throwaway folder and prints.

Then:

```bash
npm run dev     # hot reload (tsx) — development
npm run build   # tsc → dist/
npm start       # node dist/index.js — production
```

On first run with no `GROUP_*` IDs set, the bot logs the iMessage chat IDs it sees so you can map them into `.env`.

### What you need

- **macOS** on an always-on Mac (a Mac mini is ideal), with **Full Disk Access** granted to your terminal/runtime — required to read `~/Library/Messages/chat.db`.
- **Node.js 20+**.
- An **Anthropic API key** (the only hard requirement to start).
- Optional: Google OAuth (Calendar + Tasks), a finance backend for the Finance group, `whisper-cpp` + `ffmpeg` for voice-memo transcription, a Chrome extension for browser tools.

## Groups

The assistant scopes its tools and personality by chat. Each maps to an iMessage chat ID in `.env` and a `context/<group>/CLAUDE.md`. Any DM falls through to the full-access **admin** context. Turn on only the groups you want during onboarding.

| Group | Purpose |
|-------|---------|
| **admin** | Master control, system health, cross-group triage (you only) |
| **home** | Household, calendar, groceries — shared with a household member |
| **work** | Project/product development — repos, GitHub, browser |
| **finance** | Personal finance (needs a finance backend; optional) |
| **health** | Workout / nutrition / sleep, evening check-in |
| **job-search** | Job-search copilot — JD analysis, outreach |

Permissions live in `src/user-resolver.ts`. Who's who, names, and tone come from `config/profile.json` (generated by onboarding). There are also synthetic groups no one messages directly — the nightly **reflection** (22:00 ET) and the **brain-pulse** / **idea-pulse** proactive checks.

## The brain layer

Beyond replying, the assistant persists structured knowledge in a local `brownbot.db`:

- **Facts** — atomic `(subject, predicate, object)` rows with SQLite FTS5 retrieval. The system prompt gets a `--- Relevant Knowledge ---` block tailored to whatever you just asked.
- **People graph** — people + emails/phones + interactions, populated from Calendar attendees, email senders, and (optionally) Apple Contacts.
- **Nightly reflection** — scans everything new across groups, extracts durable facts, and writes a morning brief prepended to the 06:30 calendar prep.
- **Dashboard** — read-only HTML at `http://127.0.0.1:4000`, loopback-only. Reach it from your phone over Tailscale.
- **Recall** — `recall_memory` pulls everything stored about a subject in one call, so "I don't have that" only happens when storage is genuinely empty.
- **Health check** — `npm run doctor` reports whether facts are seeded, loops are firing, and backups are fresh.

### Talking to it about reminders

Surfaced tasks carry a visible `#<id>`. Reply with `snooze #N 3 days`, `cancel #N`, `done #N`, or `push #N to Friday`. The agent translates these into tool calls so future reminders respect the change.

## Configuration

Onboarding writes `config/profile.json` and `.env` for you. To adjust later, edit those directly — see [`docs/CUSTOMIZING.md`](./docs/CUSTOMIZING.md) for the profile schema and how the context files fit together. `.env.example` documents every variable; only `ANTHROPIC_API_KEY` is strictly required to boot.

MCP servers (e.g. Instacart, Spotify) are configured separately in `mcp-servers.json`, same format as Claude Desktop.

## Run on boot (launchd)

The repo ships `launchd/*.plist` agents (main loop, nightly backup, 5-min self-sync, and the KeepAlive extraction daemons). Symlink the ones you want into `~/Library/LaunchAgents` and `launchctl load` them:

```bash
ln -sf "$PWD/launchd/com.brownbot.agent.plist"  ~/Library/LaunchAgents/com.brownbot.agent.plist
launchctl load ~/Library/LaunchAgents/com.brownbot.agent.plist
```

(A symlink survives reboot and lets the optional 5-min auto-sync flow through; a plist loaded directly from the repo path runs now but won't auto-start on boot.)

## Photos & voice

iMessage photos are passed to the agent as vision input; HEIC is converted to JPEG on the fly via `sips` (built into macOS). Voice memos are transcribed locally with [whisper.cpp](https://github.com/ggerganov/whisper.cpp) (`brew install whisper-cpp ffmpeg`, then set `WHISPER_MODEL`) so audio never leaves the machine. Both degrade gracefully — if a dependency is missing, the rest of the bot keeps working.

## Privacy

- All state is a single local SQLite file. No external database.
- The dashboard binds to `127.0.0.1` with no auth — reach it remotely only over a private network (e.g. Tailscale).
- Your personal config (`config/profile.json`, the generated `context/` files, `.env`, `*.db`) is gitignored. The committed repo contains no personal data.
- Money-spending or commitment actions run only behind a propose → confirm → execute gate (`go #action:N`) with daily/weekly spend caps.
